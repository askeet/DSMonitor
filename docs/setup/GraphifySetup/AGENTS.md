## Graphify

- Automatically use the [Graphify skill](.codex/skills/graphify/SKILL.md) for code relationships and impact analysis without requiring manual skill selection. The [Project map](docs/AI/PROJECT_MAP.md) describes architecture, workflows, business rules and tests. Trivial tasks and documentation edits need no graph check.
- In PowerShell, resolve the executable with `$graphifyCommand = Get-Command graphify -ErrorAction SilentlyContinue` and `$graphifyExe = if ($graphifyCommand) { $graphifyCommand.Source } else { Join-Path $env:USERPROFILE '.local\bin\graphify.exe' }`. Use `& $graphifyExe` for every Graphify command below, including `query`, `explain`, `affected` and `update`. Test the fallback before reporting the CLI unavailable. Do not use `python -m graphify`, reinstall packages, or modify global PATH.
- Before relying on Graphify results, check `graphify-out/graph.json` build metadata, including `built_at_commit`, against `git rev-parse HEAD` and relevant working-tree changes. The build commit is also shown under **Graph Freshness** in `graphify-out/GRAPH_REPORT.md` when available. Inspect `git status --short`; if HEAD differs, use `git diff --name-status <build-commit>` to identify changes. A successful query or matching commit alone does not verify freshness: the graph can include uncommitted inputs. If indexed inputs changed or freshness is uncertain, run `graphify update .` before relying on the graph. For read-only tasks, avoid unnecessary updates; if updates are prohibited, use source directly and report `STALE`.
- With a current graph, start with `graphify query "<question>"` before broad source searches. Use `graphify explain "<symbol>"`, `graphify path "<A>" "<B>"`, or `graphify affected "<symbol>"` to narrow the result. Verify important relationships in source and read source directly for missing coverage or an unavailable graph or CLI. Include this guidance when delegating codebase exploration.
- After any code changes, whether made directly or by a delegated worker, the responsible Codex agent must run an incremental `graphify update .` from the repository root before reporting completion. Documentation-only tasks do not require an update. In the final report, state `Graphify: CURRENT` if freshness was verified and no update was needed, `Graphify: UPDATED` if an incremental update succeeded, `Graphify: STALE` if freshness is uncertain or an update was unsuccessful, or `Graphify: NOT USED` if Graphify was not relevant. Base the status on the actual checks and command results.
- After a pull, merge or branch switch, use the same freshness check and update if indexed code changed or the baseline is uncertain. The update scans the corpus and uses the manifest to limit extraction. `graphify check-update .` only checks the non-code pending marker. Build a missing or unusable graph when needed with `graphify extract . --code-only`. Keep extraction local and code-only, and use `.graphifyignore` for the bundled third-party trees.
- After delegated code changes, the coordinator must refresh Graphify before performing dependency analysis or requesting independent QA. The implementation worker does not need to update the graph.
- The existing Codex `PreToolUse` hook calls `graphify hook-check`, an intentional no-op in 0.9.112. These maintenance steps rely on the agent or operator running the commands. Installing Git hooks or other automation requires explicit approval.
